## 修复优先级

| 优先级 | 发现与依据 | 修复验收 |
| --- | --- | --- |
| P1 | 18087 的 API 二进制使用 Go 1.24.13、MCP Go SDK 1.4.0。源码与实际二进制的 `govulncheck` 主结果均报告 29 项命中，源码结果为标准库 27 项、SDK 2 项。部分涉及 HTTP 请求及 multipart 解析，应优先处理。SDK 有额外应用鉴权且 MCP 未映射宿主机端口，单凭依赖扫描无法断定每条公告在本部署中的实际影响。 | 换用仍受安全维护的 Go 工具链及修补版 SDK，重建 API、worker、MCP，按源码与实际运行产物复扫，重跑登录、上传、流式会话和 MCP 回归。 |
| P1 | MCP 工具接口已通过只读回归，数据库权限仍可写。运行中的 API、worker、MCP 共用应用数据库用户，其在业务库上具备 `ALL PRIVILEGES`。三个服务同时收到初始化账号密码以及对话、嵌入、会话和 MCP 相关密钥。单个服务失陷后影响会扩展到其他服务持有的数据和凭据。 | 把迁移和日常运行凭据分开，按服务授权。MCP 对业务表只读，审计与调用计数仅保留所需写权限。容器配置仅注入各服务实际使用的秘密。 |
| P2 | Qdrant 与 Web 等服务共用同一容器网络，当前没有配置 Qdrant API 密钥。宿主机只能访问 Web 映射端口，容器网络里的服务仍可接触向量索引。 | 缩小索引服务的网络访问范围，启用认证，限制索引读写身份，复测发布、检索、降级和恢复。 |
| P2 | 公网入口防护待补。实际 Web 响应已有 `nosniff`、`no-store` 和 Referrer-Policy，缺少 CSP 和防嵌套策略。Bearer 令牌按现有规约放在标签页的 `sessionStorage`，如同源脚本执行边界失守，脚本可读取令牌。当前 HTTP 入口只绑定本机回环。 | 公网部署前启用 HTTPS，配置经页面回归验证的 CSP 和防嵌套策略，验证登录、附件预览及流式对话。 |
