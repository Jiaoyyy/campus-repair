# 角色助手与引用核对

当前已实现三角色报修助手、管理员提示词/启停/材料与只读 MCP 工具绑定、本人私有会话、流式回答和可核对的引用。材料及原有三工具不自动绑定；新增授权工单查询工具按文末一次性迁移绑定至种子助手；管理员需到“助手设置”选择本组织资料和适用角色的工具。已支持报修人对话内草稿编辑和确认创建；已支持模型原生只读工具决策；三项完整可配置技能和通用多步工具循环仍待实施，`skill` 仍为 `none`；MCP 只能查询，模型不能派单或改变工单。

## 使用步骤

1. 管理员在知识库上传演示材料，确认已有可检索版本。
2. 在助手设置中选择角色助手，勾选材料并保存；修改配置带 version，旧版本返回 409。
3. 用户直接描述问题即可，任何角色都不需要选择资料检索算法。后端在需要时自动查询绑定资料；管理检索测试独立保留在知识库。
4. 回答完成后点击实际引用，在侧栏查看高亮原文；Escape 或关闭按钮返回原引用入口，不跳离当前对话。管理员也不能查看他人的私有会话。

没有资料或没有命中时仍调用模型自然交流、追问位置和现象、解释通用操作流程；只有涉及校方制度、维修时限等事实时说明无法确认，不能伪造资料引用。未配置对话模型时，已绑定的 MCP 工具仍可回答明确的本人工单进度、已分配任务或指定类别可派人员查询；其他问题会提示模型未配置。

## 独立网关配置

在本项目 `.env` 设置 `CHAT_BASE_URL`、`CHAT_API_KEY`、`CHAT_MODEL`，仅给后端；URL 是兼容网关前缀，服务端追加 `/chat/completions`。嵌入使用独立的 `EMBEDDING_*` 参数。配置后执行 `docker compose up -d api worker mcp`，让容器读取新环境；单纯 restart 不会加载修改后的 `.env`。`CHAT_TIMEOUT_SECONDS` 可设为 1–115 秒，默认 115；每轮总处理上限 120 秒。

2026-10-22 已使用本项目配置的真实网关，在独立环境完成三角色流式资料问答、实际引用与原文范围核对。三项技能和模型原生工具调用未在本次验收；详细结果见 [验收记录](verification.md)。`/api/capabilities` 的 assistant=true / chat=configured 仅表示参数齐全，下一次调用仍可能失败。

## 身份、绑定与来源

服务端从登录身份读取组织与角色，不接受客户端自报身份。管理检索不带 agent_id 时仅管理员可用；带 agent_id 时必须匹配本组织、当前角色及已启用助手，并只检索其绑定的材料。两路结果在 RRF 前回读 MySQL 复核当前 generation 与绑定。

模型只能引用本轮最多四个候选的 `[1]` 等编号。返回来源只包含回答实际引用且最终仍授权的片段，不能把所有候选当引用；非法编号在发送到浏览器前移除，并显示“无法验证”。结束本轮时在事务中锁定并复核身份、配置版本和材料版本，变化时不宣称回答完成。

来源接口另外要求消息属于本人会话、状态 complete、切片确为该消息引用，并复核助手绑定和材料当前版本。解绑、停用、角色改变或重建发布后，旧来源不可继续打开；历史正文仍归本人，失效引用会被移除并提示。引用编号校验保证来源关系和访问范围，不证明模型对材料的解释一定正确。

普通模型回答完整缓冲后检查危险维修指令和常见无证据业务断言，再向前端发送正文；生成过程中提供phase阶段提示。配置模型时通过原生function calling生成严格只读查询计划，再经现有MCP Host/Server执行；业务结论与描述从实际工具结果生成。模型不能指定身份、执行写动作或绕过绑定。未配置模型时保留原有明确关键词查询作为降级。详见 [MCP 说明](mcp.md)。

## 流与持久化

- 流建立前校验失败使用普通 JSON 错误。开始后先 meta，再 delta，最后唯一 done 或 error；心跳为 SSE 注释。
- meta 含 conversation_id、message_id、request_id、skill、agent_version。done 含 answer、实际 citations、warning；error 含 code、message、partial，不能当完整答案。
- 每轮上下文仅本人最近 10 条 complete 消息及当前输入。失败/取消轮的输入和部分回答不进入后续上下文。
- 查询正文经校验后保存，普通模型正文完整缓冲；取消、超时或流中断后保留 failed/cancelled 状态，未核验的缓冲文字不作为正文发布。浏览器停止后可用“重读历史”核对服务端状态，不自动重试模型。
- 同一会话生成锁保存在 MySQL，最长 130 秒；重复发送 409。API 每 15 秒、读历史和开始新轮时回收过期锁，将遗留消息标为中断。进程重启不会立即抢占尚未到期的锁。
- Nginx 不缓冲流、读取超时 130 秒；API 对话路由 125 秒并单独延长写超时，人工接口仍使用原 10 秒请求预算。

## 隔离验收

按知识库文档启动带 `compose.knowledge-check.yaml` 的 `campus-repair-check` 环境，运行：

```sh
python3 apitest/verify_assistant.py
```

模拟网关支持正常、假引用、无引用、危险步骤、非法工具、慢流、中断、超时和协议错误。脚本会强杀隔离 API，并通过调整隔离会话租约模拟等待到期，未把它记录为真实等待 130 秒。所有材料和消息为虚构数据，模型请求仅保存在忽略目录 `tmp/knowledge-mock`；审计只存请求/资源/结果等元数据。

真实网关集成验收另用以下命令，会发起少量真实模型调用：

```sh
docker compose build api web
python3 apitest/verify_gateway.py
```

脚本从本项目 Compose 配置读取网关，仅在内存中组装测试配置；新建随机名称的 `campus-repair-gateway-*-check` 项目、独立数据库/向量库/文件卷及随机账号密码，不使用模拟网关、不改日常助手绑定。默认测试端口 18085，可用 `--port` 指定空闲端口。验证成功后将虚构回答、引用及请求标识写入忽略目录 `tmp/`，无凭据；无论成功失败均停止本次容器，保留演示数据卷。该脚本验证资料问答与确定性 MCP 路由，不替代技能、模型原生工具循环或公网验收。

## 页面与配置操作

桌面左侧显示紧凑历史，对话区单独滚动，输入区留在底部；手机按需展开历史。示例问题只填入输入框，不会自动发送。生成失败或主动停止保留明确的未完成状态。

助手设置分为基本信息、绑定材料和实时查询工具。材料可按名称搜索，选择数量不随搜索过滤丢失；查询工具优先显示中文用途，MCP 名称可在技术信息中核对。保存区固定在表单底部，显示未保存状态；切换助手、刷新、撤销、离开设置和退出登录前可继续编辑或明确放弃更改。浏览器刷新有未保存提醒。版本冲突保留编辑内容，并在保存区显示错误，需刷新后重新编辑。

## 自动资料与自然交流

对话请求仅需 content。后端对普通问候直接调用模型，对报修相关问题结合近期本人上下文查询资料；没有已绑定且发布的材料时不调用嵌入服务。存在可用配置时优先混合检索，失败后回退关键词并在回答中明确降级。全部检索失败仍可整理信息与追问，但显示“资料查询暂不可用”，不把故障伪装成没有校方规定；真实模型故障仍返回未完成错误。

资料引用只用于实际提供的授权片段。没有材料不等于不能聊天，但也不能因此确认校方时限、虚构人员/工单状态或声称已创建报修。自然对话本身不等于三项可配置技能已完成；本轮新增对话草稿能力见文末。对话中不再提供任何角色的高级检索选择；关键词/向量/混合测试只在知识库管理使用。

## 对话式报修（2026-10-23）

报修人说“宿舍灯坏了，帮我报修”后，助手整理类别、具体位置与故障描述，缺少必填信息时继续追问。对话内卡片可编辑类别/位置/描述，点击“保存修改”后可刷新并重新打开历史恢复；切换对话、离开或刷新前提醒未保存修改。取消草稿不创建工单，也不改变已有工单。

只有主动激活“确认提交报修”按钮才会调用正常创建接口，输入框回车及保存修改不建单。失败保留草稿；请求结果不确定时从服务端核对状态。成功在对话内显示真实编号和“查看工单详情”，可直接打开原有详情页。相同内容重试沿用服务端幂等键，实际修改后换键，已提交卡片不可再次编辑或重复建单。

结构化提取使用真实对话网关；JSON内部缓冲，不展示部分卡片。位置、现象仅接受用户输入片段；格式错误、未知字段或虚构字段返回本轮失败，原有效草稿保留。提取失败可重新提问或从“返回工单”进入人工报修。AI与MCP继续只读，写入由登录报修人在业务界面确认。本次未完成三项可配置技能、安全/派单辅助技能或模型原生tool-calling。

docker compose -p campus-repair-draft-check --env-file tmp/draft-check.env -f compose.yaml -f compose.verify.yaml -f compose.knowledge-check.yaml -f compose.draft-check.yaml up -d --no-build

专用覆盖层使用 `tmp/draft-mock`，不与已有知识库隔离环境共用模拟状态。真实网关可运行 `python3 apitest/verify_gateway.py --draft-only` 做草稿专项；不加参数则同时验证自然对话、草稿、嵌入、三路检索、引用与MCP。失败会保留本次已采集的脱敏证据，不把未完成结果记为通过。

## 三角色多场景对话（2026-10-23）

| 角色 | 可以直接尝试 |
| --- | --- |
| 报修人 | “宿舍灯坏了，帮我报修”“我的报修还有多少单未结束”“有哪些报修待我确认”“查工单RP…” |
| 维修人员 | “我现在有多少工单要处理”“今天派给我的有哪些活”“有哪些工单待接单”“照明维修有哪些安全要求” |
| 管理员 | “我现在有多少工单要处理”“有哪些单等我审核”“今天新增了多少报修”“照明工单推荐安排谁” |

查完工单可以接着说“那照明的呢”“只看今天”“全部类别”“不限日期”。每次都会重新查询授权业务数据；问候或资料问题后不把无关短句自动当作筛选。管理员缺少人员类别时先追问，“照明的”可接上；人员建议用真实候选及待接单/处理中负载，不执行派单。让助手直接改状态时会指向人工确认入口。

待我处理和未结束不是同一数量。管理员待办是待审核/待派单，报修人是待补充/待确认，维修人员是待接单/处理中。今天按北京时间：管理员/报修人指今天创建，维修人员指今天指派。模型查询支持近7天、昨天、本周、上周、本月和明确日期范围，以及地点/故障关键词；每次一个类别。未配置模型的关键词降级仍仅支持原有筛选。

业务回答显示计数与卡片，点击可打开真实工单；卡片标出查询时间，历史记录是快照，最新进度以详情为准。快照中的工单在读取历史时重新核对归属，改派后不再给原维修人员详情入口。列表最多5条，计数覆盖所有匹配记录。人员卡片与知识引用分开显示，未绑定查询工具或MCP故障不会显示编造的零工单。

页面欢迎语、示例、输入提示按角色显示；助手消息显示实际助手名称。发送后显示查询/资料/整理阶段，完成时读取历史不清空消息区；失败或停止后可主动“重新提问”，不会自动重试模型。快捷追问只填入输入框，由你发送。

新增 `query_work_orders` 默认通过迁移6绑定至种子助手，只执行一次；旧工具和材料绑定不变，助手启停不变。管理员可在助手设置解绑，重启不会恢复。自定义助手需要手动发现/绑定；共享工具不会放宽组织与归属权限。已实现原生模型单次只读查询决策；仍不代表完整三项可配置技能或通用多步Agent循环。

隔离验收新增 `python3 apitest/verify_scenarios.py`，使用与草稿验收相同的独立项目/配置，覆盖角色数量、筛选上下文、日期、历史权限、解绑重启、故障和无模型查询。脚本会重建隔离API以验证无模型配置，不能在日常环境运行。

## 地点、故障和日期的连续查询

可以直接问“研发楼最近有什么故障”，再说“那3号楼呢”“只看漏水”“再往前一周”。最近默认含今天近7天，回答及卡片显示北京时间起止日期、完整匹配总数及最近最多5条真实故障描述。位置/故障按字面片段查询，不做模糊语义召回；名称与记录不一致时需换更准确的位置。查询失败、解绑或非法模型参数明确失败，不当作零记录。查询结论来自本轮实际成功工具，无工具的普通回答若出现常见查无记录/数量断言则拦截。此检测不能证明任意自然语言事实一定正确，卡片与授权工单详情仍是核对依据。

查询整栋楼可直接说“研发楼有什么问题”，无需补充楼层；只问楼名与问“研发楼一楼怎么了”都不会默认增加日期。想看当前待修问题，建议问“研发楼有哪些未解决问题”，按未结束状态查询，不会排除较早创建的工单。管理员欢迎区已采用这一示例。明确说“最近”时仍按创建/指派时间筛选近7天：最近没有新增记录不表示没有旧的未解决工单，空结果会解释该区别。新的完整楼栋问句清除旧时间，短追问如“那3号楼呢”继承有效日期；“问题”“故障”等泛称不会自动作为描述关键词。

模型每轮先选择只读查询或继续对话，普通问答额外需要一次计划调用；当前采用单次计划+单次查询，未实现模型读取结果后自行多步调用。明确草稿起始和写操作保留受控入口；有效草稿期间仍可切换查询。普通正文先核验再展示，生成中显示阶段提示。工具仍有单次10秒、每轮最多3次硬限额，本路径每轮只执行1次，单轮总预算120秒，无自动重试。

真实语义专项：`python3 apitest/verify_semantic_gateway.py`，使用随机独立环境、虚构工单和实际网关；确定性失败专项：`python3 apitest/verify_semantic_failures.py`，仅使用已配置的campus-repair-draft-check环境。

## 网关限制与后端版本核对

日常API、worker、MCP必须同镜像，更新后运行python3 apitest/verify_backend_deployment.py；仅ready=200不足以证明工具可用。query_rate_limited表示模型网关429，query_quota_exhausted表示明确额度不足，query_gateway_unavailable表示其他网关HTTP错误，均未查询工单；query_plan_failed才表示计划结构/参数校验失败。不会自动重试。额度不足需恢复网关服务后才能继续模型查询，人工工单页面和内部只读MCP不依赖模型额度。

## 网关连接失败排障（2026-10-28）

query_gateway_unavailable也包括连接拒绝、DNS/TLS故障、请求或流读取超时；页面明确说明连接不可用或超时，保留可编辑原问题与人工入口。不能把这类失败解释成用户问题不清楚。日志仅记录固定connection/timeout分类，不输出底层错误中的地址和凭据。模型已配置时，大多数问题先经过原生查询计划，该阶段连接失败会使普通问答与业务查询一起失败；不会自动绕过计划、权限或工具绑定。

本次确认：本机Karing VPN提供的网关合成解析无法完成TLS，而两处公共DNS核对的真实地址通过同域名证书校验后可以访问。仅在本项目生成被Git忽略的`compose.override.yaml`，为API/worker/MCP增加网关`extra_hosts`。默认`docker compose`自动加载，因此普通重建会保留本机修复；隔离验收显式指定`-f`文件，不加载该覆盖。原HTTPS域名、证书校验及凭据保持，未修改系统VPN或全局DNS。

此覆盖是本机网络的临时修复，不应分发为通用服务器配置。网关IP变化或VPN解析恢复时，应重新核对DNS与同域名TLS；撤销时把该覆盖文件移到忽略目录备存，再统一重建API/worker/MCP。若未来增加其他本机覆盖，先合并配置，不直接覆盖已有文件。网关根地址或`/models`成功只证明对应连接/鉴权可用，不证明额度充足或模型生成成功；仍需单独授权和记录真实生成验收。

## 现有功能稳定化（2026-10-23）

失败或停止后原问题恢复到输入框，可直接编辑；失败消息旁提供“编辑问题”“重新提问”“前往工单”。只在明确点击重问/发送时发起新请求。停止按钮有独立key和显式button类型，并阻止默认提交；取消完成切回发送按钮时不会因同一次点击意外重发。失败/停止后消息区自动定位恢复操作，手机按钮换行可见。

普通回答、业务结果均在最终身份/配置/来源复核和完成事务成功后发送正文。故障不发布未核验缓冲正文/卡片；如果完成已保存而网络最后一段断开，重新读取历史核对服务端结果，不自动重问。成功回答后的历史刷新失败只提示刷新错误，不将回答改成生成失败。有有效草稿时，字段未变化且未明确发起新报修的普通话题不再重复替代草稿。

SSE客户端支持UTF-8及CRLF跨字节分片、多行data、心跳和兼容扩展；校验meta、消息ID、事件字段及终止事件，拒绝乱序、当前批次重复终止、无效JSON及截断。读到合法终止后关闭连接，不等待后续事件。工具参数同时拒绝null/非字符串/重复键，不将无效筛选解释为默认全量。

模拟回归入口：`python3 apitest/verify_stability.py`，仅允许实际运行mock依赖的campus-repair-draft-check。开始前保存助手配置/fixture模式，成功或失败均恢复，清除仅测试环境的登录限流；会产生虚构工单和会话，禁止对日常执行。独立流解析器测试：`node --experimental-transform-types apitest/assistant_stream_checks.mjs`（Node24）。本轮不请求真实chat/embedding网关，真实验收继续等待额度恢复。

## 问题发现与总结（2026-10-30）

可以问“总结当前有哪些问题”“最近出现最多的问题是什么”“现在有几单白跑了”“有几单上门异常”，也可限定位置、类别和日期并追问。助手先取得全部授权记录的聚合事实，再让模型选择重点、提出建议；不会只看最近5张工单推算高发。统计与建议分开，相关工单按需展开，历史保留原统计时间。

近期默认近7天（含今天、北京时间）；白跑按实际到场无人记录次数并显示涉及工单数，不能当下降比例。当前上门异常可能重叠，去重合计；“创建满7天未结束”仅供关注，不是校方超时承诺。类别、准确位置、相同描述排名不等于已查明根因，也不推断楼栋结构。模型只引用本轮实际事实ID，不能编写统计数、已通知/派单等断言；建议仍待现场核实。

统计失败显示真实失败；统计成功但建议服务不可用时，卡片保留事实并明确“本轮未生成模型建议”，不自动重试。用户可重新提问。普通聊天、资料问答、筛选、人员负载和报修草稿继续使用原流程。管理员欢迎问题现覆盖总结、高发和白跑。
