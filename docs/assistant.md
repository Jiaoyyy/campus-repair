# 角色助手与引用核对

当前已实现三角色报修助手、管理员提示词/启停/材料与只读 MCP 工具绑定、本人私有会话、流式回答和可核对的引用。默认不自动绑定材料或工具；管理员需到“助手设置”选择本组织资料和适用角色的工具。三项技能、报修草稿表单衔接及模型原生工具调用仍待实施，本轮 `skill` 固定为 `none`；MCP 只能查询，模型不能派单或改变工单。

## 使用步骤

1. 管理员在知识库上传演示材料，确认已有可检索版本。
2. 在助手设置中选择角色助手，勾选材料并保存；修改配置带 version，旧版本返回 409。
3. 用户直接描述问题即可，任何角色都不需要选择资料检索算法。后端在需要时自动查询绑定资料；管理检索测试独立保留在知识库。
4. 回答完成后点击实际引用，在侧栏查看高亮原文；Escape 或关闭按钮返回原引用入口，不跳离当前对话。管理员也不能查看他人的私有会话。

没有资料或没有命中时仍调用模型自然交流、追问位置和现象、解释通用操作流程；只有涉及校方制度、维修时限等事实时说明无法确认，不能伪造资料引用。未配置对话模型时，已绑定的 MCP 工具仍可回答明确的本人工单进度、已分配任务或指定类别可派人员查询；其他问题会提示模型未配置。

## 独立网关配置

在本项目 `.env` 设置 `CHAT_BASE_URL`、`CHAT_API_KEY`、`CHAT_MODEL`，仅给后端；URL 是兼容网关前缀，服务端追加 `/chat/completions`。嵌入使用独立的 `EMBEDDING_*` 参数。配置后执行 `docker compose up -d api worker mcp`，让容器读取新环境；单纯 restart 不会加载修改后的 `.env`。`CHAT_TIMEOUT_SECONDS` 可设为 1–115 秒，默认 115；每轮总处理上限 120 秒。

2026-10-22 已使用本项目配置的真实网关，在独立环境完成三角色流式资料问答、实际引用与原文范围核对。三项技能和模型原生工具调用未在本次验收；详细结果见 [验收记录](verification.md)。`/api/capabilities` 的 assistant=true / chat=configured 仅表示参数齐全，下一次调用仍可能失败。

## 身份、绑定与来源

服务端从登录身份读取组织与角色，不接受客户端自报身份。管理检索不带 agent_id 时仅管理员可用；带 agent_id 时必须匹配本组织、当前角色及已启用助手，并只检索其绑定的材料。两路结果在 RRF 前回读 MySQL 复核当前 generation 与绑定。

模型只能引用本轮最多四个候选的 `[1]` 等编号。返回来源只包含回答实际引用且最终仍授权的片段，不能把所有候选当引用；非法编号在发送到浏览器前移除，并显示“无法验证”。结束本轮时在事务中锁定并复核身份、配置版本和材料版本，变化时不宣称回答完成。

来源接口另外要求消息属于本人会话、状态 complete、切片确为该消息引用，并复核助手绑定和材料当前版本。解绑、停用、角色改变或重建发布后，旧来源不可继续打开；历史正文仍归本人，失效引用会被移除并提示。引用编号校验保证来源关系和访问范围，不证明模型对材料的解释一定正确。

模型输出按完整句子暂存后检查常见危险维修指令，涉及拆卸/接线等表达时使用应用固定的安全提醒，不发送相应模型步骤。当前 MCP 路由由服务端识别常见自然查询并通过真实 SDK 调用；例如报修人问“我报的维修到哪一步了”、维修人员问“今天派给我的有哪些活”。管理员未指定故障类别时先追问，下一轮“照明的”可结合本人上下文查询；模型返回的 tool_calls 仍按协议失败处理，不执行模型自报工具或身份。详见 [MCP 说明](mcp.md)。

## 流与持久化

- 流建立前校验失败使用普通 JSON 错误。开始后先 meta，再 delta，最后唯一 done 或 error；心跳为 SSE 注释。
- meta 含 conversation_id、message_id、request_id、skill、agent_version。done 含 answer、实际 citations、warning；error 含 code、message、partial，不能当完整答案。
- 每轮上下文仅本人最近 10 条 complete 消息及当前输入。失败/取消轮的输入和部分回答不进入后续上下文。
- 每段已发送正文写入 MySQL；取消、超时或流中断后保留 failed/cancelled 状态及部分正文。浏览器停止后可用“重读历史”核对服务端状态，不自动重试模型。
- 同一会话生成锁保存在 MySQL，最长 130 秒；重复发送 409。API 每 15 秒、读历史和开始新轮时回收过期锁，将遗留消息标为中断。进程重启不会立即抢占尚未到期的锁。
- Nginx 不缓冲流、读取超时 130 秒；API 对话路由 125 秒并单独延长写超时，人工接口仍使用原 10 秒请求预算。

## 隔离验收

按知识库文档启动带 `compose.knowledge-check.yaml` 的 `campus-repair-check` 环境，运行：

```sh
python3 apitest/verify_assistant.py
```

模拟网关支持正常、假引用、无引用、危险步骤、非法工具、慢流、中断、超时和协议错误。脚本会强杀隔离 API，并通过调整隔离会话租约模拟等待到期，未把它记录为真实等待 130 秒。所有材料和消息为虚构数据，模型请求仅保存在忽略目录 `tmp/knowledge-mock`；审计只存请求/资源/结果等元数据。

真实网关集成验收另用以下命令，会发起少量真实模型调用：

```sh
docker compose build api web
python3 apitest/verify_gateway.py
```

脚本从本项目 Compose 配置读取网关，仅在内存中组装测试配置；新建随机名称的 `campus-repair-gateway-*-check` 项目、独立数据库/向量库/文件卷及随机账号密码，不使用模拟网关、不改日常助手绑定。默认测试端口 18085，可用 `--port` 指定空闲端口。验证成功后将虚构回答、引用及请求标识写入忽略目录 `tmp/`，无凭据；无论成功失败均停止本次容器，保留演示数据卷。该脚本验证资料问答与确定性 MCP 路由，不替代技能、模型原生工具循环或公网验收。

## 页面与配置操作

桌面左侧显示紧凑历史，对话区单独滚动，输入区留在底部；手机按需展开历史。示例问题只填入输入框，不会自动发送。生成失败或主动停止保留明确的未完成状态。

助手设置分为基本信息、绑定材料和实时查询工具。材料可按名称搜索，选择数量不随搜索过滤丢失；查询工具优先显示中文用途，MCP 名称可在技术信息中核对。保存区固定在表单底部，显示未保存状态；切换助手、刷新、撤销、离开设置和退出登录前可继续编辑或明确放弃更改。浏览器刷新有未保存提醒。版本冲突保留编辑内容，并在保存区显示错误，需刷新后重新编辑。

## 自动资料与自然交流

对话请求仅需 content。后端对普通问候直接调用模型，对报修相关问题结合近期本人上下文查询资料；没有已绑定且发布的材料时不调用嵌入服务。存在可用配置时优先混合检索，失败后回退关键词并在回答中明确降级。全部检索失败仍可整理信息与追问，但显示“资料查询暂不可用”，不把故障伪装成没有校方规定；真实模型故障仍返回未完成错误。

资料引用只用于实际提供的授权片段。没有材料不等于不能聊天，但也不能因此确认校方时限、虚构人员/工单状态或声称已创建报修。当前基础对话不等于三项可配置技能和带确认草稿表单已经完成。对话中不再提供任何角色的高级检索选择；关键词/向量/混合测试只在知识库管理使用。
