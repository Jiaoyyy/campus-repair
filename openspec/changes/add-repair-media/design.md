# Design

## Context

人工建单为带幂等键的 JSON 事务，详情由同一工单授权过滤。会话草稿也调用现有创建逻辑。纯文字 JSON 请求保持兼容。

## Decisions

- 每单最多 6 张 JPEG/PNG，原图每张最多 25 MiB，另可附 1 段 MP4/MOV，最多 20 MiB、15 秒。服务校验实际内容，限图像像素、视频分辨率和并发解析。浏览器尽可能先压缩照片，服务端保留正确方向，以长边 2560px 的 JPEG 重新编码，单张保存版本不超过 5 MiB；视频用 FFmpeg 规范为浏览器可播放的 MP4 并去掉额外流和元数据。大图按原始方向上传的行为须在实机验收。
- 人工建单有附件时用 multipart，请求仍按原幂等键重复提交。输入及原上传文件摘要共同进入幂等签名。媒体分行以 BLOB 保存，和工单、事件、审计在同一事务写入，避免失败留下孤立文件。现有工单可无附件。提交前可以移除附件。
- 附件元数据及文件按工单现有授权独立读取，文件始终经过登录和当前归属校验。附件使用服务端生成的名称及确定的 Content-Type。浏览器只按需取得视频，图片缩略显示并支持打开预览。媒体不进入 MCP、模型或知识库。
- 代理限制请求字节和上传等待，单次 multipart 容量上限 81 MiB。API 限制并发解析、执行超时及视频解码参数。缩略图与视频载入失败可重试，表单上传失败保留输入及文件。

## Risks / Trade-offs

- 文件加大数据库及备份容量，首版严格限制单文件与数量；试点观察容量再决定对象存储与配额。
- 手机相册中的 HEIC、超限视频及超大原图需要先在设备转换或剪辑。错误提示列出可接受的格式和限制。
- 已读取到用户设备的文件无法通过后续改派远程撤回。新的请求始终复核归属。

草稿附件留在浏览器，保存文字草稿不上传文件。仅本人确认时使用现有 multipart 建单入口，一并校验草稿归属、版本、幂等摘要并原子保存。普通对话和无模型的类别追问共用服务端类别目录。
