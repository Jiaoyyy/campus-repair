# Proposal

## Why

现有四项只读MCP工具能够查询工单与人员，但缺少工单完整进展、处理历史和上门安排的统一查询。助手业务回答大量使用固定模板，已有草稿、RAG与人员查询能力尚未形成可配置、可追踪的三项技能，用户难以快速判断当前情况及下一步。

## What Changes

- 扩展内部MCP白名单，增加工单详情与按需时间线、上门安排、授权知识检索；为现有待办查询补充待办原因、责任角色及业务页面入口，复用现有筛选和分析能力。
- 建立故障信息补全、安全自查建议、派单辅助三项内置技能的定义、版本、角色约束、启停和助手绑定，每轮至多执行一项技能。
- 统一查询、技能和回答的编排，支持最多三次必要的只读MCP调用；遇到条件不足时追问，所有调用继续由服务端校验。
- 增加基于已授权事实的简短解释，先回答用户问题，再给出必要依据及有权限的下一步入口；精简正文与结果卡片的重复信息。
- 将管理员角色提示词与所选技能指令用于对应回答生成，保存实际技能、版本、工具证据及阶段耗时，验证网关请求内容与历史兼容。
- 保留正常业务接口确认建单、危险操作拦截、引用复核和完成前权限检查；配置撤销、模型故障和重试均具备明确行为。

## Capabilities

### New Capabilities

- `repair-mcp`: 扩展内部只读工具目录、详情/上门/知识查询、待办下一步以及有界工具编排。
- `repair-assistant-skills`: 三项内置业务技能的配置、路由、版本与执行证据。
- `assistant-answer-quality`: 以用户问题为中心的证据回答、提示词作用范围、卡片展示与效率验收。

### Modified Capabilities

当前主规约目录尚未归档任何能力。沿用MVP变更中的 `repair-mcp` 路径并追加需求，另两项细化原 `repair-assistant` 的技能与回答规划。同步MVP的proposal、design、tasks及四工具白名单表述，保持原已完成记录；实施和验收进度见tasks.md，交叉审核完成后再核对原MVP任务。

## Impact

涉及后端MCP Server/Client、查询计划、agents配置、会话生成与证据复核，前端助手设置和回答卡片，以及独立apitest。复用已有工单/上门授权、RAG和草稿确认事务，增加技能配置迁移与兼容字段。现有四工具保留原输入输出契约，新增工具由管理员显式绑定。已有三次限额、10秒超时和审计纳入扩展验收。MarkItDown、多格式上传、外部MCP地址、业务写工具与公网交付继续按原待办管理。

## Follow-up Change

2026-11-17用户在18087反馈总结空泛、统计范围混用，并明确要求模型自主总结及组织正文，模板提供可选参考。后续变更improve-assistant-natural-answers承接本变更的七工具、技能配置和授权证据，拟替换compose_business_answer预写句子渲染、固定分析格式及机械技能措辞，并重新验收回答质量。18/19项为此前实现及对应自动测试记录，用户问题链的质量验收待后续变更完成。后续行为以新变更规划为准，当前代码仍按本次实现运行，归档前按依赖顺序核对两份变更。
