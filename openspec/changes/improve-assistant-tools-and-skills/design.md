# Design

## Context

变更前通过官方Go MCP SDK实现四项只读工具，Host与Server均校验身份和绑定，已有三次原子限额、10秒超时及审计。`chat.go`调用查询计划器后，业务结果主要由 `formatBusinessResult` / `formatMCPAnswer` 格式化；分析建议使用独立模型请求。普通问答的 `buildChatMessages` 包含角色提示词，计划器、草稿提取和分析建议使用固定指令。

已有agents、agent_tools、agent_materials及会话/草稿结构，尚无完整技能定义与绑定；meta的skill固定为none。工单详情、上门业务规则、RAG与引用回读可复用。用户已确认Issue #4审核结束，两环境已更新引用修复。本变更实施及隔离验收进度见tasks.md，当前等待人工交叉审核。

## Goals / Non-Goals

本轮实现三项技能配置与实际执行证据，并让扩展查询能够解释进度、原因和下一步。复用现有业务事务、权限判断、角色隔离、草稿确认及RAG，保留旧接口和历史读取。

任意技能代码上传、任意外部MCP地址、模型业务写工具、MarkItDown与公网交付继续按原范围管理。工具编排限制为当前问题需要的最多三次只读调用。

## Decisions

### 1. 工具目录与复用边界

以下名称为本次设计选择，沿用现有四工具并增加三项白名单工具。考虑到时间线与单张工单详情共享授权和定位，二者合并为一个工具的按需字段；避免独立读取造成多余调用。

| 工具 | 输入 | 返回与复用 |
| --- | --- | --- |
| get_work_order_detail | number、include_history、cursor、limit | 当前授权详情、责任角色、最近维修记录；时间线默认20条、最多50条、稳定游标与has_more |
| get_work_order_visit | number | 方便时间、确认预约、出发/到场、白跑、备件及当前阻塞，复用上门业务规则 |
| search_repair_knowledge | query、limit | 默认5片段、最多10片段，复用当前助手材料绑定、混合检索、降级状态、generation与原文定位 |
| query_work_orders扩展 | 原筛选参数，增加可选include_next_steps | 原计数/列表不变，按需增加待办原因、责任角色、动作代码和证据标识 |

三项新工具初次迁移仅登记发现目录，管理员显式绑定。新增字段为可选扩展，旧客户端可忽略。Server从签名调用身份取得agent_id、真实用户及组织，参数不得指定身份、SQL、URL或文件路径。详情与上门查询复用当前业务授权，历史片段也按当前归属过滤；动作只返回站内已知路由的代码，由前端解析并重新读取详情。

工具结果统一带queried_at、资源版本及稳定事实标识，知识结果另带材料与发布generation。空记录、权限拒绝、依赖故障分别处理，无权和不存在使用一致的不可见资源响应。时间线游标包含排序依据并受同一工单及当前权限约束。

知识检索通过共享服务层复用原RAG管线，统一引用注册与最终复核，防止普通资料分支与MCP分支重复检索同一问题。MCP服务只具备所需只读检索能力。

### 2. 技能模型与配置生命周期

三项内置定义采用稳定标识repair_intake、safe_self_check、dispatch_advice，每项包含definition_version、角色、用途、触发条件、required_fields、allowed_tools、指令与输出契约。复用原设计的skills及agent_skills关系，定义随代码迁移发布，启停和助手绑定按组织配置。管理员编辑启停、绑定及角色提示词，内置定义版本随部署更新。

管理API为现有agents配置增加skill_bindings及技能目录，保存时使用助手version并在事务内校验组织、角色和有效定义。技能与工具绑定分别管理，绑定技能缺少依赖工具时展示配置缺项，执行时返回明确不可用，不能越过绑定直接查库。

升级仅为原种子助手一次性建立适用技能绑定，以衔接既有草稿/安全问答/人员建议体验；原助手停用及工具解绑保持有效，自定义助手需显式绑定。迁移完成后不再自动恢复技能绑定，重复启动保持管理员修改。已有有效草稿继续通过正常业务入口确认。

### 3. 路由和工具编排

每轮读取当前助手、技能启停与工具绑定，形成受控候选；用户明显报修或补充有效草稿时选repair_intake，安全问题选safe_self_check，管理员明确请求候选建议时选dispatch_advice。一般工单进度/详情查询可作为基础只读能力，记录skill=none。复合意图若需要两项技能则先澄清当前任务。

明确意图快速路由，原生计划器可通过函数参数中的skill_id补充语义技能选择，Host校验并移除该路由元数据后再向MCP发送严格业务参数，服务端对所选技能重新校验角色、启停、版本和依赖。复用模型原生function calling生成严格计划。允许根据首个查询返回的真实工单标识进行必要详情或上门查询，避免预先猜测标识。Host维护本轮结果表，按工具名和规范化参数复用结果，不跨轮复用实时事实。每次调用共享同一request_id，Server保留原子三次计数；调用取消继承本轮context，每次10秒且总轮次不超过现有120秒期限。失败终止依赖调用，保留已授权结果供降级复核，不自动重试。

### 4. 回答、提示词与证据

回答模型输入依次包含固定权限/安全规则、当前角色说明、所选技能定义和输出要求，再加入不可信的用户上下文及本轮授权事实。角色说明用于普通问答、业务解释和分析建议。计划器和草稿提取继续采用严格字段协议，仅接收适用的角色/技能上下文；管理员文案不能改变输出schema或工具授权。

简单计数和状态由服务端直接回答，减少一次模型生成；原因、下一步与多事实解释使用模型组织。业务生成复用原生函数调用流解析，通过仅用于答案组织的compose_business_answer返回结构化段落；模型可选事实ID与动作代码在本轮schema中枚举，服务端继续校验，每段携带evidence_ids和可选action_code，事实数值、人员、状态、时间及动作取自对应服务器事实，拒绝未知ID、矛盾值和无依据动作。可变业务值通过受控事实引用渲染，模型负责选择重点及组织解释。自由建议独立标明待核实，经过危险步骤和不实业务声明检查；无法验证时退回有效事实卡片。单纯依赖引用ID无法证明自然语言正确，需要固定问法和对抗输出验收同时约束措辞。

模型无权读取的事实不进入请求，凭据不进入提示词。模型生成完成后统一事务复核身份、助手/技能版本、材料绑定/generation和相关业务归属；状态版本变化时拒绝以旧动作发布为当前可执行建议。正文与业务快照保存保持一致，持久化失败不发布完成事件。

### 5. 展示、证据与耗时

正文先给一至两句直接答复，必要时补依据和下一步，复杂说明可展开，不设机械字数截断。结果卡片承载数量、完整状态、查询时间、截断提示、详情及原文。按问题选择卡片内容，避免正文与卡片逐项重复。旧kind与字段保留，新增详情/上门结果及技能元信息为兼容扩展。

会话保存skill_id、skill_version、助手版本及受控证据快照，SSE meta/done返回实际值，旧消息字段缺失按未记录处理。审计关联request_id、工具、结果状态、最小资源标识和各阶段耗时。网关接受请求后记录角色提示词哈希、角色/技能指令存在性及技能版本，供核对实际请求，避免记录完整对话、提示词或密钥。

分别记录planner、draft_extract、MCP、RAG、answer_generation和最终发布的耗时/调用数。以同一虚构数据对照改动前后，报告端到端及阶段p50/p95、模型请求数和工具次数；真实样本不足时明确样本量，不声称统计稳定或预设未经验证的提速比例。仅阶段反馈先行，正文保持校验后发布。

## Risks / Trade-offs

- 模型解释可能偏离事实，采用结构化证据、受控业务值和失败降级，并验证无依据原因、假人名、错误日期及注入输出。
- 新增详情读取可能泄露改派后的旧记录，所有工具及历史回读复用当前授权并测试改派和账号撤销。
- 多次调用增加等待，在本轮去重、默认有限返回并优先简单直答，以实测确定调用收益。
- 技能升级可能改变原草稿体验，通过一次性种子绑定、旧草稿保留和停用后的人工入口验证兼容。
- 角色提示词影响范围扩大，固定协议与安全约束保留服务端执行，测试修改提示词后的真实请求及越权拒绝。

## Migration Plan

1. 扩展技能定义/绑定与会话元数据迁移，原数据结构与读取兼容；备份同一时点数据库和上传卷并记录运行配置。
2. 在独立mock环境验证旧数据升级、重复启动、管理员主动解绑、失败恢复及并发保存。现有四工具的协议和契约回归保持通过。
3. 按任务执行三角色协议、技能、回答及引用回归，少量真实网关核对请求内容、真实结果与耗时，单列实际成本和失败记录。
4. 先在保留数据的人工审核环境部署统一API/worker/MCP镜像，核对配置与运行镜像、业务摘要及人工验收。日常环境按用户授权安排更新。
5. 回滚保留数据卷和新增兼容字段，使用原镜像与原绑定配置；迁移必须保证旧版本可读取，禁止通过删除卷回滚。新技能及扩展工具不再被旧版本执行，已存在草稿继续由兼容正常接口处理。

## Follow-up Change

2026-11-17用户在18087反馈总结空泛、统计范围混用，并明确要求模型自主总结及组织正文，模板提供可选参考。后续变更improve-assistant-natural-answers承接本变更的七工具、技能配置和授权证据，拟替换compose_business_answer预写句子渲染、固定分析格式及机械技能措辞，并重新验收回答质量。18/19项为此前实现及对应自动测试记录，用户问题链的质量验收待后续变更完成。后续行为以新变更规划为准，当前代码仍按本次实现运行，归档前按依赖顺序核对两份变更。
