# Spec Delta

## Purpose

通过真实 MCP 协议为智能体提供有限的业务查询能力，使工具发现、绑定和调用均可验收，并把用户身份、组织和资源归属带入每次服务端授权，防止模型伪造身份或执行写操作。

## ADDED Requirements

### Requirement: 协议初始化、发现与绑定
系统 SHALL 使用 MCP Client 与 Server 的初始化和协商流程，支持 tools/list 和 tools/call，不得以普通业务函数改名代替协议。管理员只能绑定已发现且在白名单内的工具；每轮调用再次核对智能体、工具绑定、启用和角色范围。首版不允许配置任意外部 MCP 地址。

#### Scenario: 协议验收
- **WHEN** 测试客户端初始化连接并发现工具
- **THEN** 返回协商版本和工具输入结构，后续调用得到协议结果，可从协议记录验证

#### Scenario: 未绑定或被停用工具
- **WHEN** 模型请求未绑定或已停用工具
- **THEN** 调用被拒绝，不访问数据，记录拒绝原因

### Requirement: 只读工具及调用权限
系统 SHALL 仅暴露查询本人工单、查询已分配任务、查询可派人员三种只读工具。分别仅供报修人、维修人员、管理员使用；结果限本组织，工单查询按归属过滤，人员查询只返回 ID、显示名称、负责类别、待接单/处理中数量。工具不得提供联系方式、密码、令牌或无关数据。

#### Scenario: 查询本人工单
- **WHEN** 报修人经工具请求工单状态
- **THEN** 仅返回本人本组织工单及允许的进度字段，与业务页面一致

#### Scenario: 报修人查询派单人员
- **WHEN** 报修人请求仅管理员允许的可派人员工具
- **THEN** 返回权限拒绝，不返回人员信息

### Requirement: 可信身份与二次校验
系统 MUST 从登录身份产生受信任调用上下文，MCP Server 验证上下文有效性并重新查询当前账号状态与权限；不得采用模型参数中的用户 ID、组织或角色。不存在与无权工单 SHALL 使用一致的无可见资源响应。未知工具及任何写操作请求 SHALL 被拒绝。

#### Scenario: 伪造参数身份
- **WHEN** 模型在工具参数中伪造管理员或他人用户 ID
- **THEN** 按真实调用用户执行或拒绝非法参数，不扩大结果范围

#### Scenario: 失效身份或写工具
- **WHEN** 登录已撤销，或调用未提供的派单工具
- **THEN** 调用拒绝，工单状态不变，并记录失败结果

### Requirement: 工具故障与调用证据
系统 SHALL 对每次调用记录请求标识、真实操作者、工具、最小必要参数、耗时及成功/拒绝/失败；服务超时或协议错误返回明确失败，不编造实时数据。单轮最多三次只读调用，每次超时上限 10 秒，超过限额终止工具循环；失败不阻断人工工单页面。

#### Scenario: 工具超时
- **WHEN** 工具超过 10 秒无有效结果
- **THEN** 终止该调用并提示暂不可查询，不宣称已取得实时工单数据
