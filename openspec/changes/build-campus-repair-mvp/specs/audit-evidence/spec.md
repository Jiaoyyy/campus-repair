# Spec Delta

## Purpose

为业务操作、权限拒绝和 AI 调用提供可核对证据，使小组能够用页面、接口、日志与测试说明实际完成度，同时限制审计可见范围和敏感内容，记录真实贡献而非预设结果。

## ADDED Requirements

### Requirement: 审计记录与权限
系统 SHALL 记录登录结果、权限拒绝、工单创建与状态变更、派单改派、知识库和配置变更、检索、技能及 MCP 调用。记录含请求标识、真实操作者或匿名标记、组织、动作、资源、时间和结果；成功工单变更与审计原子保存。管理员仅可分页查询本组织审计，不可通过界面改写或删除；其他角色不能查看审计列表。

#### Scenario: 追踪一次派单
- **WHEN** 管理员完成派单并按工单筛选审计
- **THEN** 可核对操作者、前后状态、人员、时间与请求标识，并与工单时间线一致

#### Scenario: 审计不可写
- **WHEN** 数据库不能保存成功状态变更的审计
- **THEN** 业务变更整体失败，不出现工单已更新但审计缺失的结果

### Requirement: 敏感数据最小化与统计
系统 MUST 不在日志、错误或审计中记录密码、完整令牌、模型密钥或完整私有对话；只保留必要资源 ID、技能/模型名称、状态、耗时等元数据。管理员 SHALL 查看本组织按工单状态与故障类别计数，不能包含其他组织记录；派单负载统计仅计待接单和处理中。

#### Scenario: 脱敏检查
- **WHEN** 用测试令牌和密钥完成登录及模型调用后检查日志与审计
- **THEN** 不包含秘密原文，仍能关联请求及判断结果

### Requirement: 可复现验收与贡献记录
交付 MUST 包含接口文档、自动化验收和三角色端到端流程，覆盖匿名、越权、跨组织、并发、重试、模型/检索/MCP 故障及重启。测试 SHALL 使用模拟依赖获得可复现结果，并另外记录实际网关和公网演示结果；未执行场景不得标为通过。贡献记录按成员关联提交、PR、任务和验收证据。

#### Scenario: 对照规约答辩
- **WHEN** 小组展示项目完成度
- **THEN** 每项已完成任务能关联实际运行证据和验证结果，未完成项明确列出
