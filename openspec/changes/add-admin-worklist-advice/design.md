## Context

现有工单查询和人员工具各自需要绑定，工作台详情已有带版本复核的审核与派单操作。

## Decisions

初审继承上一轮待审核查询范围，每页五单。模型逐单提供建议和依据，缺信息的工单给出追问。存在危险线索或模型结果无法核实时转人工。浏览器通过已有业务接口逐单确认审核；仅成功回执中的工单进入本次人选建议，派单需再次确认。

复用管理员派单辅助技能。建议工具按原授权范围读取工单，按更新时间及 ID 排页，每页五单并优先展示该页风险线索。最近范围按查询时北京时间近七天创建时间过滤。同次查询的建议快照随消息保存，模型及初次卡片仍只读取首批。旧卡补查沿用原筛选与时间锚点，排除已保存的首批，逐页标注为补查，补查行通过详情办理。新卡翻页复核会话、角色、绑定和工单权限，并标注当前状态与是否已变更。页码及本卡逐单人选和回执随刷新恢复，本页派单仍经现有业务接口。

候选 ID、姓名、负载及工单版本来自只读结果。浏览器仅在管理员点击确认后逐单调用已有 assign 接口，分别展示成功与失败。旧快照需重新查询才能取得候选 ID。紧急程度追问沿用上轮待派范围。Enter 发送，Shift+Enter 换行，输入法选词期间保留回车。

同次初审一次读取范围内的工单及版本，分批生成建议并随消息保存。卡片每页展示五单，在浏览器切页。更新状态或重新打开历史时，逐单读取授权状态与版本，保留原顺序和意见。仅本轮快照版本一致且仍待审核的建议通过项可勾选。新初审请求生成新卡。旧消息只展示已保存的工单。

通过语义路由区分讨论已有建议和请求实时查询。讨论读取同会话、当前权限可见的初审原文和最近回复，以自然语言解释或修正意见。保留当时卡片及工单状态；识别不了指代时请用户指出对应单。

服务端从已完成消息和持久化快照恢复初审来源与所选工单，独立于最近十条文本。显式引用须同时匹配本人会话、原卡、快照成员及当前授权。单卡单页可解析序号；多卡或多页时引导点选已保存的工单。历史问题使用原卡；当前状态读取对应编号的授权详情。新初审成为默认来源。

审核指令直接进入待审核初审；“最近”限定近七天创建。询问数量、查看状态和讨论既有建议分别走原查询或解释入口。受理时结合类别、地点和报修原话判断，定位到楼层厕所或明确走廊即可，不强制追问厕位、房间号或诊断细节。

初审先识别风险，再识别明显缺失的地点。楼栋占位符即使带房号也不能作为可到场地址；原卡保留意见，历史建议通过项按当前地址提示核对。

首行展示地点与初审建议标签，类别和编号同行展示当前状态；建议理由单列。

待派单卡和审核成功批次共享换人操作。按类别查询当前同组织可派人员与负载，手选 ID 随来源消息逐单保存，失效时提示重选。预约请求按维修人员串行核对其他有效预约，两个时段首尾相接允许；冲突保留原记录。
