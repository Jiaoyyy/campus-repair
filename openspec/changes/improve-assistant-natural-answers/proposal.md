# Proposal

## Why

用户在18087审核“总结当前有哪些问题”时，收到泛化建议和混合时间范围的统计，难以获取具体信息并继续追问。现有实现把模型约束在固定JSON、预写句子与机械措辞中，需要让模型充分使用MCP提供的信息，自主总结和回答问题。

## What Changes

- 由模型结合用户问题、有效上下文和授权工具结果，自主组织总结、解释、比较及追问，模板提供可选写作参考。
- 调整业务回答、分析建议及技能指令，移除预写句子选择、固定“建议”开头、统一数字禁令和固定段落数量等表达门槛。
- 保留MCP结构化数据及来源，补充当前问题、各指标时间口径和关联工单证据，修正“当前问题”被默认近期创建范围误导的行为。
- 在现有调用预算内，根据工具返回的信息选择必要的后续只读查询，支持“具体哪几单”“为什么”“依据在哪”等连续追问。
- 正文按问题决定是否交代日期：当前快照先给结论，期间和比较说清影响结论的范围，完整口径在依据中可查。
- 正文由模型生成，引用与站内入口使用经校验的结构化信息，卡片按需展示明细，普通查询在紧凑卡片中展示匹配数、有效筛选和状态，点击后展开相关工单。
- 增加基于用户原始问题的回答质量验收，记录有用性、具体性、事实依据和追问表现，补足原有协议及权限测试。
- 对明确询问本人全时段未结束数或待本人处理数的报修人，复用现有授权查询直接返回数值及卡片；用同一组问题对照调用次数、事实、范围和耗时。

- 将助手调整为以消息为主的单列布局，合并页头操作、压缩输入区，将历史移到按标题搜索和分页的侧栏。

- 报修求助先说明与故障相关的安全注意事项，优先使用可核对的授权材料。模型筛选故障事实并整理草稿，只追问缺失信息，保留本人确认。

## Capabilities

### New Capabilities

当前主规约目录为空。沿用在途变更中的能力路径，新增本次细化需求，后续按依赖顺序合并到主规约。

- `assistant-answer-quality` — 模型自主总结、自然回答、证据核对、展示及实际问题验收。
- `repair-mcp` — 当前问题查询口径、关联证据和基于工具结果的后续读取。
- `repair-assistant-skills` — 以处理方法为核心的技能指令及可选回答模板。

### Modified Capabilities

主规约暂无可直接修改的已归档能力。本变更承接`improve-assistant-tools-and-skills`与`improve-assistant-insights`，提出替换固定正文生成和默认分析口径的后续行为。相关在途设计添加衔接说明，原测试结果保留其实际验证范围，回答质量缺口在本变更重新验收。

## Impact

涉及backend/internal/app中的chat、semantic_query、business_answer、insights、skills、business_query和会话证据管理，以及frontend/src中的Assistant、BusinessResultCard、消息与引用类型。复用七个MCP工具、三角色授权、RAG、草稿确认事务、调用预算和审计。更新助手/API/MCP说明、验收记录及handoff，具体实现全部列入待办。本轮为推理应用链路改进，训练数据收集和agentic RL由后续实际评测结果决定。

维修任务清单在解释缺少可核实依据时直接展示核对后的状态及数量。
