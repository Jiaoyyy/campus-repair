# Design

## Context

当前代码已有七个真实MCP工具、三项可配置技能、本轮工具缓存、三次原子调用预算、单工具10秒及单轮120秒期限。chat.go先生成一次查询计划，后续详情读取主要由预设分支决定。business_answer.go要求模型调用compose_business_answer选择事实ID，再由服务端拼接预写句子。insights.go要求固定notes JSON、固定建议开头和数字限制，formatAnalysis继续按固定顺序拼正文。safe_self_check定义版本2也带有固定句数和版式限制。

分析默认recent近七天，当前异常与积压又按不限创建日期计算。前端以同一时间范围标题展示这些结果，并在total为零时输出“没有匹配工单”。analyzeBusiness向模型提供聚合事实与分组，但缺少关联工单记录。这些代码位置是本次修改入口。

现有business_answer_test锁定预写句子输出，verify_skill_execution与verify_tools_gateway含固定语句断言，需改为核对问题、事实和引用。原权限、并发、取消及引用检查继续作为回归依据。

## Goals / Non-Goals

本轮交付以proposal及三份specs为范围。模型承担自然总结和问答，服务端提供授权信息及业务校验。MCP调用继续采用当前三次预算，按结果动态选择后续读取。此前讨论的六次预算作为尚未采纳的建议保留在讨论历史中，后续用实际失败样例评估调整需求。

模型训练、agentic RL、更多故障类别和外部工具接入另行立项。当前七工具及现有业务接口承担本次信息获取与人工确认。

## Decisions

### 1. Model-authored Answers

普通问答、业务详情、统计分析和人员解释共用自然回答入口，输入包括用户当前问题、有效上下文、角色提示词、选中技能的方法指令及实际工具结果。模型可以选用自然段、列表或表格，模板仅提供按需参考。简单计数也允许由模型自然表达，模型依赖不可用时由已有事实降级路径明确呈现可用数据。

报修人用明确完整的句式询问本人的未结束数或待本人处理数时，复用原有直接计数分支和 `query_work_orders`，按固定 `active` 或 `action` 范围查询。Host 校验返回范围，用已核实总数生成一句回答，保留业务卡、持久化与发布前复核。短追问、限定日期或地点及复合问题继续由现有流程解释。隔离评估比较两种口径、跨用户数据、零结果、追问、工具失败及重试，区分模拟耗时与真实网关耗时。

业务解释退出compose_business_answer的选句渲染路径。分析退出固定notes JSON及formatAnalysis正文拼装路径。SSE、持久化及历史继续保存正文、证据和可选业务结构，卡片字段独立承载明细，旧消息按原结构读取。结构化草稿提取、工具参数及页面入口仍使用严格协议。

保留固定句子拼接曾有实现和验证成本较低的优势，但用户审核已暴露表达和总结不足。对新正文采用开放表达与证据校验相结合的设计。

### 2. Tool-result-driven Reading

扩展现有网关原生工具调用解析，使一次模型响应可表达一个合法工具调用或最终自然正文。通过 `answer_repair_question` 的单一 `body` 字段传输完整正文；模型可使用登记表证据键，也接受能核实的量值转述。工具调用消息与对应结果按网关协议配对进入下一次请求，模型据此决定是否继续读取。每次请求仅开放当前角色、助手绑定及有效技能允许的工具。普通问候保留直接回答入口。

复用turnToolCache、Host/Server权限检查、request_id限额与超时，最多三次实际MCP调用。结果去重后直接返回已取得数据，检测重复无进展的模型调用并转入最终回答，避免空循环。模型解释及计划请求同样受单轮期限约束，记录实际模型/工具次数与阶段耗时。到达预算后仅允许根据已有事实回答并说明缺失范围。异常及取消停止依赖链，用户可主动继续提问。

仅将已核实用户输入或工具结果中的工单标识用于后续调用。新轮次解析指代及条件变化后重查实时数据，历史权限敏感正文沿用现有清理策略。多对象指代无法确定时正常追问。

### 3. Explicit Query Scope

groundAnalysisQuery对“当前问题”采用不限创建日期的当前快照，明确近期新增才使用相应创建时间窗口，高发和白跑按用户表达选取原有期间规则。每项事实补充时间依据，模型同时取得各自范围，前端在对应明细处展示。total为零只描述所属查询范围。正文生成器将查询范围元数据与可直接引用的值分开。完整口径保留在工具结果和卡片，正文证据登记表提供可单独引用的起止日供必要时使用。提示词指导模型根据问题自然表达当前、期间新增、事件和相比窗口。

query_work_orders分析结果增补各异常/积压指标的关联工单证据，复用服务端过滤条件和只读事务。概要包含真实工单标识、位置、状态、负责人、阻塞类别、查询时间和资源版本，详情按需交给现有详情/上门工具。原列表继续承担示例语义，显式关联列表独立标明总数及截断。沿用原字段及默认返回行为，通过可选参数支持按指标读取有限工单页，每页最多5条。游标绑定指标、筛选及授权范围，校验后再次执行当前归属过滤。并发更新造成页间变化时显示查询时点并允许刷新，完整计数继续由聚合计算。

### 4. Evidence Validation

工具结构化结果保留事实标识、工单版本、查询时间和知识generation，向模型提供可引用的来源标记。正文允许自然转述和正确表达数字，页面链接通过受控资源引用解析。统一校验引用是否实际取得、链接对象是否授权、关键数字/日期/人员/状态是否与所引用证据一致，检验明确的矛盾及危险内容，移除原先统一数字禁令和固定句式判断。

正文在完成前缓冲并执行证据、权限及版本复核，通过后发布。发现非法来源、危险步骤或伪造动作时保留复核事实并提示解释失败。仅部分段落包含无法匹配的原始数字或标识时，保留其余通过校验的段落并说明结果不完整，禁止自动重试模型。可核对的关系包括数量的统计范围、工单与状态、候选与负载、记录与时间及材料片段来源。自然语言语义还由固定问题集和人工审核评价，单独的标记存在性不能证明任意句子正确。

引用继承知识原文权限与安全过滤，合法禁止提醒保留实际来源。来自工单描述和资料的指令作为不可信内容处理。模型关于优先级的判断要说明实际依据及待核实信息，已发生动作必须有本轮业务记录支持。草稿本人确认、派单和状态转换继续由正常业务接口校验。

### 5. Skill Versions and Presentation

将三项技能指令整理为用途、关注信息、处理方法、工具范围和领域约束，移除安全技能中固定句数及禁止列表等版式规则。本次修改到的定义发布新版本，组织启停与助手绑定沿用现有迁移策略。角色提示词在自然回答请求中的传递继续使用已接受请求的脱敏指纹验证。

Assistant保留模型正文为主要阅读内容。BusinessResultCard按需展示统计明细、工单和原文。普通查询把匹配总数和查询时点放在一行，按需呈现生效的筛选范围、状态和必要提示。相关工单默认折叠，仅在样例少于匹配总数时补充可查看条数。通过原入口查看单张工单。通用说明和固定追问按钮从普通查询卡片移除。分析卡片删去与正文重复的固定“建议关注”正文块。Markdown按安全白名单展示，表格可在自身区域横向滚动，任意模型HTML及未核实链接拒绝渲染。移动端、刷新、返回和旧卡片均复核。

助手在桌面和手机使用同一列消息布局。单行工具栏提供切换助手、新建和历史入口。输入区随文本增高并设上限。历史仅在需要时打开，以日期分组，通过本人会话的分页接口按标题搜索；打开旧对话时保留快照时间提示。

报修人描述故障并求助时，报修补全技能结合本人已提供的信息及本轮授权资料生成简短提醒和必要追问。模型在同一请求里选择一个或多个可核实的现象片段，服务端校验并整理为草稿描述。提醒优先引用适用的材料，检索缺失、引用失效或生成内容危险时保留通用安全提醒和草稿入口。单独的安全资料问答继续使用安全技能。

### 6. Answer Quality Evaluation

先固定虚构数据及实际问题集，再实现生成链路。问题至少覆盖当前总结、近期新增、异常具体工单、延期原因、优先级、证据追问、前后期间比较、计数、人选、草稿补充、安全引用及无依据问题，包含三角色和话题切换。每项保存问题、范围、预期信息、实际正文、工具轨迹、证据、耗时及人工评语。

事实、权限及证据错误直接判失败。正常问题还需直接回应，包含数据足够支持的具体信息，解释使用依据，连续追问对象连贯。存在匹配工单却只返回泛化关注建议判失败。接受同义表述和不同版式，消除绑定旧固定句子的断言。

mock负责可重复故障、对抗及并发路径，真实网关限定问题验证自然总结与连续问答，并保存实际费用边界和失败记录。用户审核问题链作为独立验收项。原变更18/19描述其先前实现及测试，本轮质量缺口在新任务中重新验证。

## Risks / Trade-offs

- 自然表达增加事实偏离的可能，采用受控证据、明确关系核对、发布前复核、对抗输出与人工实际问答共同验证。
- 动态补查增加请求与等待，复用已有三次预算、去重、停止条件和阶段记录，用相同虚构数据报告实测。
- 多指标范围和分页可能让模型混淆，结果中明确每项口径、样例和完整计数，覆盖零新增与历史积压同时存在的夹具。
- 为追求格式一致重新加入机械门槛会削弱回答能力，验收接受不同措辞与版式，并直接检查有效信息。

## Migration Plan

1. 在独立mock环境建立问答基线并保存原工具、配置、草稿与历史摘要。
2. 完成查询范围、证据扩展、动态读取、自然回答及技能指令，兼容旧工具及消息字段，按实际定义变化升级技能版本。
3. 完成单元/协议/原七组回归、质量问题集、浏览器及隔离真实网关验收，记录全部失败和实际改进范围。
4. 保留数据和配置，将统一API/worker/MCP镜像及配套web部署到18087，核对ready、业务及上传摘要，交由用户和队友执行问答审核。
5. 独立环境演练保留卷回滚到实施前镜像，确认旧客户端与历史兼容。审核完成后核对前置变更和MVP任务，按依赖顺序同步规约及归档。

维修任务查询解释校验失败时，以授权快照生成状态摘要，并在历史读取中修正旧版校验提示对应的正文。
