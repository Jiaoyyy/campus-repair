# Spec Delta

## Purpose

让校园报修助手能根据当前登录人有权查看的真实记录，识别高发问题、上门异常及积压，并将事实统计与模型建议分开展示，帮助人工判断下一步，避免把关键词匹配或最近几单当作完整分析。

## ADDED Requirements

### Requirement: 识别分析意图
助手 SHALL 区分普通筛选、问题总结、高发分析、白跑与上门异常分析；显式白跑/高发问句不得作为故障描述关键词执行。模型可解析自然问法与后续范围变化，服务端仍验证参数和原工具绑定。

#### Scenario: 高发与白跑
- **WHEN** 用户问“最近出现最多的问题是什么”“现在有几单白跑了”或“有几单上门异常”
- **THEN** 分别返回高发归纳、真实白跑记录和当前异常分析，不能用描述包含“白跑”或“上门异常”的普通工单列表冒充结果

### Requirement: 全量授权聚合与明确口径
分析 SHALL 聚合全部匹配记录，并显示时间与授权范围；报修人仅本人，维修人员仅当前指派，管理员仅本组织。高发按故障类别、准确位置、相同描述分组，稳定排序并处理并列；不推断楼栋结构或故障根因。用户明确提到的授权准确位置不得在分析时被静默省略；互不包含的多个准确位置须先明确单一范围。近期默认含今天7个北京时间自然日。白跑按实际no_show时间统计次数与去重工单数；当前异常不受工单创建日期限制，三类允许重叠，合计使用去重数。积压按创建已满7天且尚未结束识别，不虚构SLA违约。

#### Scenario: 样本不足与隔离
- **WHEN** 匹配记录超过5条且包含其他组织或他人记录
- **THEN** 排名和总数基于全部授权记录，示例最多5条且独立标明；不泄露其他组织、他人或旧指派工单

#### Scenario: 时间与异常
- **WHEN** 当前异常来自较早创建工单，或同单同时备件等待和上门超时，或多次白跑
- **THEN** 当前异常仍包括该单、合计不重复；白跑次数与涉及工单数分别展示，并按no_show发生时间应用日期

### Requirement: 有依据的问题发现与建议
回答 SHALL 先说明关键发现和依据，再展示相关工单；分析总结提供高发分布、当前阻塞与积压事实。模型根据实际事实ID选择重点、解释关注方向并给出人工可执行的建议，建议标明待核实，不得添加未知人数、数量、已完成动作或确定根因。所有统计数来自服务端，模型输出须完整解析和校验后发布。

#### Scenario: 总结问题
- **WHEN** 用户要求总结当前问题或建议优先处理什么
- **THEN** 显示真实的高发与阻塞依据，模型建议引用本轮事实；没有相应事实时不编造趋势、原因或百分比

### Requirement: 失败降级与只读边界
MCP/数据库/鉴权失败 SHALL 显示真实失败，不能当作零问题；统计成功但模型建议失败时 SHALL 保留事实并明确本轮未生成模型建议，不自动重试。分析不修改工单、草稿或安排，不新增写工具；历史显示快照时间，相关工单按当前权限重新检查。并发对话沿用单轮锁与配置版本/会话确认，失败或取消可恢复。

#### Scenario: 建议服务失败
- **WHEN** 统计成功但模型超时、限流、输出无效事实ID或不合法结构
- **THEN** 仅返回真实统计和明确降级说明，不显示无依据建议；重试须用户主动发起
