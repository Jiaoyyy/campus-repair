# Design

## Context

现有query_work_orders已具备授权筛选、重复读事务、MCP二次身份/绑定校验、历史结果与SSE。业务回答目前直接模板化；只有5条示例，未汇总上门。动机见proposal。所有工作保留当前未提交代码与review人工数据。

## Goals / Non-Goals

**Goals:** 在现有只读工具上增加明确analysis参数，完整统计后让模型参与重点选择和建议，事实始终由服务端生成。

**Non-Goals:** 不扩展写权限、自动派单、通知、预测故障、推断根因或无依据趋势；不实现通用无限工具循环。

## Decisions

- query_work_orders增加analysis枚举overview/frequent/no_show/exceptions，继续同一绑定与授权链，避免新工具自动扩大授权。语义计划增加分析说明；显式白跑/异常/高发问句在验证后做窄意图校正，避免模型再次当keyword。没有模型时仅显式分析可返回事实，并标明未生成建议。
- 分析时对用户原话中明确出现的、当前有权查看的准确位置做只读核对，模型漏掉该位置时保留最长明确匹配；互不包含的多个准确位置要求明确单一范围，防止静默扩大。片段/整栋范围仍由原语义计划解析。
- BusinessResult增加analysis结构及kind=analysis，旧orders/candidates兼容。全量分类、准确位置及相同描述用GROUP BY稳定排序；前五条只能作为示例。当前异常独立使用原visitQueue条件，以同一组织/归属及非日期筛选统计，合计OR去重；白跑用no_show_at日期而不是created_at。重复读事务保证本轮事实一致。
- 分析事实使用稳定ID、标题、真实值和说明。模型只能引用本轮ID并提出建议，结构化JSON缓冲校验、长度/ID/数字及写动作断言约束，不让模型重新编写统计数。建议明确为待核实，不能把描述中的命令当系统指令。失败保留事实并标记降级；没有自动重试。
- 复用已有模型流接口做一次建议生成，随后才finishTurn并发布；沿用配置版本、会话检查、取消和对话锁。只为分析增加一次模型调用，普通查询不增加成本。
- 管理员侧栏移除独立上门按钮，保留workbench路径作为管理内部页签，避免修改既有历史模型；详情仍记录原from。设置说明直接删去，服务端和文档约束保留。ui-ux-pro-max两次文案查询未匹配，精简依据为用户明确反馈和项目决策，不称数据库推荐。

## Risks / Trade-offs

- 同位置/描述不能代表真实根因 → 标明准确位置与相同描述，不做语义合并和因果诊断；并列标识，超出前五仍说明是排名截取。
- 当前阻塞与期间新增统计不同 → 每项标明口径，去重合计；日期限制不错误排除旧异常。
- 模型建议仍需人工判断 → 引用核实事实、建议单独标识，结构失败降级；不作为维修安全指令。
- 分析增加成本与耗时 → 一次计划、一次MCP、一次建议，沿用超时与停止，无隐式重试。

## Migration Plan

先在独立draft-check执行模拟/权限/失败/重试/并发验证，真实模型使用隔离样本少量核实。升级前记录daily/review业务摘要；构建同一后端镜像更新API/worker/MCP和web，不改配置绑定、不重灌、不删卷。统计只读核对业务数据，聊天记录新增单独计数；保留旧镜像可回退。
