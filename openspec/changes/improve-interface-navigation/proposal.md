# Proposal

## Why

人工验收发现主要操作被上门信息和历史挤到下方，助手输入区会随卡片变高而离开视口，原生选择框和页面返回路径也不统一。先改善三角色实际工作路径，再开展完整业务验收。

## What Changes

- 工单详情优先呈现状态、故障和当前主要操作，上门安排及历史分层；列表突出待办与下一步。
- 助手占用可用视口，消息独立滚动，发送/停止始终留在输入区；历史和卡片不能撑高整页。
- 全站选择框使用统一的可键盘操作控件，包含禁用、必填、焦点、长选项和手机表现。
- 增加可刷新恢复的页面路径与浏览器前进/后退；详情返回真实来源，导航不注销会话；未保存编辑受保护。
- 将管理员“上门协调”明确为“上门异常”，显示入列原因、当前负责方和具体下一步；查看入口直达工单上门信息，不承诺尚无的管理员处置能力。待办按钮清除筛选并定位到实际列表，重复点击仍有可见反馈。
- 仅剩取消或改派等次要操作时，将入口并入报修信息底部；只有用户展开后才显示表单，不为低频操作保留独立大卡片。
- 按ui-ux-pro-max已核实规则建立项目设计规范，统一深绿导航/浅色工作区、紧凑概览、字体间距、语义色、表单和助手；手机菜单补可见关闭与键盘焦点管理。
- 检查手机、短视口、长文本、空态及加载失败，改善信息密度和主次操作。

## Capabilities

### New Capabilities

- `interface-navigation`：三角色页面层级、连续工作路径、视口内对话与统一控件。

### Modified Capabilities

无已归档主规约；本变更细化未归档MVP的视觉一致性与上门工作台要求，不宣称MVP全部完成。

## Impact

仅调整React前端、相关验证与文档，不改变业务API、服务端权限、状态规则或AI/MCP只读边界。升级日常及独立验收web容器，保留既有数据、模型配置及人工修改。
