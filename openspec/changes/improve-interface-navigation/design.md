# Design

## Context

已读取README、handoff、MVP及上门体验变更。main.tsx使用view状态，无浏览器路由；助手卡片通过:has规则把对话面板扩大到780–900px；详情先渲染全宽VisitPanel再渲染侧边业务操作。所有原生select散落在表单中。现有验收环境有80张虚构工单和人工修改，必须保留。

## Goals / Non-Goals

**Goals:** 修复真实操作路径及全站共享控件，使用现有React/CSS完成，无需新外部依赖。

**Non-Goals:** 不调整API、权限、业务状态、模型协议或数据，不重做品牌，不触发自动派单或自动建单。

## Decisions

- 使用hash路径及History API管理列表、工作台、助手和详情，登录初始化replace当前入口，后续导航push；路径只含页面和工单ID，不含凭据或业务正文。相比引入路由库，现有少量页面无需增加依赖。记录历史索引、来源页面与页面滚动位置，列表重读保留既有可见结果并明确刷新状态，避免高度坍缩破坏返回位置；popstate遇未保存编辑先恢复当前项，再显示离开保护；确认后才重放历史移动。
- 列表、工作台及助手首次访问后保持挂载，隐藏时暂停可暂停的读取；保持筛选、分页、列表页面滚动位置、对话及消息区滚动位置；会话ID按用户保存在当前浏览器会话，刷新后用正常授权接口恢复。详情返回历史来源；直接打开详情使用角色主页作为回退。新建表单纳入脏状态及beforeunload保护。
- 详情重排为状态、简要故障与主操作、上门安排、资料及时间线；主要业务表单放在宽工作区域，次要操作折叠。上门操作保留完整权限和冲突提示，避免折叠正在编辑内容。
- 助手父级采用视口高度flex布局、min-height:0与独立overflow；移除所有按卡片强行撑高面板的规则；业务结果优先显示结构化卡片，重复回答说明折叠查看；移动历史为受限浮层/折叠区域。使用visualViewport应对软键盘尺寸变化。
- 共享Select使用combobox/listbox与portal，保留原生隐藏表单校验和值语义；键盘、外部点击、滚动重定位和禁用沿用原表单约束。全站替换相同选择框。日期保留原生时间编辑能力并统一外观。

## Risks / Trade-offs

- 历史与未保存编辑交互复杂 → 验证取消、确认、前进、直接路径、刷新、角色切换及会话失效。
- 自定义选择框可能损失原生可访问性 → 保留表单校验，明确ARIA、键盘与焦点，并实际检查手机和短视口。
- 保持挂载可能隐藏后台请求 → 工作台按active控制读取，助手仅首次访问挂载；未完成生成继续受离开保护。

## Migration Plan

前端构建与定向验证后，仅重建并更新日常18083和人工验收18087的web服务；先记录业务数据摘要，更新后复核，保留原镜像可回退，不重置或重灌测试数据。


## Review feedback refinement

用户指出“查看待办”重复点击无变化，“上门协调/查看并协调”不说明实际用途。本轮只调整现有功能的表达和去向：管理员入口改为“上门异常”，继续使用同一只读工作台API；三类异常以原因、角色负责方和下一步呈现。已出发但逾期只能表述未记录到场，不能断言未到现场；白跑后依据是否需要新时间及时间有效性区分报修人与维修人员；待备件优先显示维修人员恢复责任并保留再次上门义务。使用服务端as_of判断，刷新失败不更新事实。工作台队列与页码按用户保存在当前浏览器会话，详情刷新后返回也恢复原队列，不保存业务正文。

管理员卡片按钮改为“查看上门记录”，路径#/orders/{id}/visit直达详情的上门区域并保持来源与返回；该路径不增加任何写权限。详情重用相同异常说明，避免再次出现泛称“请协调”。列表待办按钮重置类别、位置、状态与分页，定位并聚焦列表标题，显示重复点击也能理解的反馈。切换异常队列先清除旧队列卡片，避免新标题下短暂显示旧数据。


## Secondary-only detail refinement

当当前角色没有主要业务动作时，取消/待接单改派入口复用ActionForm但并入报修信息底部，初始仅显示紧凑文字按钮；点击后在原卡内展开原因/人员及确认表单，保留版本、加载、保存错误和未保存保护。详情仅在存在主要动作时保留操作侧栏，避免取消入口挤窄故障内容。主要审核、派单、接单、处理、确认操作仍使用原优先区域，不改变权限或提交接口。


## Unified visual system

用户明确要求使用ui-ux-pro-max统一设计。自动生成结果不适合本产品，未采纳整套方案；使用已核实的Minimalism & Swiss Style、标题层级、非颜色独占状态、焦点遮挡及Web触控规则，加上技能静态清单的渐进披露、语义色和统一间距，在design-system/campus-repair/MASTER.md记录人工设计决策与来源。

保持品牌绿色，以深色导航和浅色工作区形成结构区分；新增design.css集中管理最终语义token与组件外观，沿用style.css的既有布局和业务结构。概览合并为分段面板，待办条压缩高度；异常卡片按故障/责任/下一步和记录入口组织，减少重复说明。共享PageHeading增加装饰性图形，字体不依赖外部服务。手机输入使用16px、常用触控44 CSS px；数据元信息保持较小字阶但核对对比度。

导航菜单补可见关闭和焦点循环，点击入口先关闭菜单再走原未保存保护，避免菜单焦点约束与离开确认叠加。所有表单、路由、草稿确认、AI/MCP与后台契约保持不变。验证范围覆盖三角色、知识/设置/登录、长消息与草稿、来源抽屉、手机/横屏、键盘和减少动态效果；不由此声称实机或完整无障碍认证。
