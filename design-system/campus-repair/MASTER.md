# 校园报修 UI 设计规范

日期：2026-10-30。适用范围：报修人、维修人员、管理员的现有Web页面。

## Design Intent

清晰、可靠、便于连续处理工作的校园设施服务平台。采用深绿导航与浅色工作区、简洁网格、紧凑概览、明确主次操作。主区域优先显示工单与下一步，文字解释按需展开。保留已有绿色品牌、业务和数据。

此规范由本项目需求与已核实的ui-ux-pro-max条目整理，属于项目设计决策。两次自动整套方案分别匹配运维状态页和物联网，未采纳或写为适用方案；不套用营销页、全站深色、监控指标或外部字体。

## Verified Guidance

- `styles.csv` / `minimalism-and-swiss-style`：企业工具的简洁网格、清楚字体层级、少装饰。
- `ux-guidelines.csv` / Heading Hierarchy：真实h1/h2/h3语义不因视觉改变而跳级。
- Focus Not Obscured (Minimum)：固定页头/保存区不完全遮挡焦点；与Enhanced AAA区分，不能宣称全站已符合WCAG。
- Touch Target Size：Web与原生单位不能混用；本项目主动将手机常用按钮/输入设为44 CSS px，属于产品取舍。
- Color Only：状态同时有中文文字和形状/标记，不只依赖颜色。
- `quick-reference.md`：统一间距、视觉层级、渐进披露、可预测返回、危险操作分离、减少动态效果。
- React表单继续使用真实onSubmit、必填验证、禁用与错误保留；不因19.2参考条目而迁移当前19.3业务提交机制。

## Component Rules

- 每个页面一个h1，标题图形纯装饰，主次动作、标题和内容通过字号/位置/边界共同分层。
- 概览合并为分段面板，当前队列有文字、底色与指示，不用四张高卡片重复占空间。待办条缩为紧凑提示，定位功能保留。
- 列表以故障位置、状态与下一步、处理人、更新时间、进入动作形成稳定阅读顺序；长编号和中文能换行或在容器内截断。
- 只有取消或改派时，沿用信息卡底部紧凑入口；主要业务表单保留优先区域。
- 助手仍由可用视口控制高度，消息独立滚动；历史、长卡片及草稿不能推出输入区。
- 原文/配置/表单、选择框、状态提示、加载与空态使用相同控件与语义色；业务失败不能伪装空结果。
- 手机菜单提供可见关闭入口、Escape、焦点循环；选择当前页也关闭菜单。未保存离开保护继续生效。

## Review Refinement

按2026-10-30人工审核：设置分组无需重复说明显而易见的字段和内部权限规则；列表保留状态与操作按钮，删除重复动作小字。管理员侧栏以报修管理为首，上门异常放入内部页签；错误、未保存、危险影响与统计口径仍须可见或可展开。问题分析先给事实和建议，排名明细与示例工单按需展开，不重复堆叠全量卡片。文案搜索未获得适用条目，这些取舍来自用户反馈与项目设计决策。

## Validation Boundary

测量实际渲染的颜色对比度、点击区域、焦点位置和溢出，并记录三角色/桌面/手机的实际结果。设计建议不是实现证据；实机软键盘、屏幕阅读器、其他浏览器等未测试内容仍单独标注。
